# Stage 1: Scaffold

← [Master plan](00-master.md) · Next: [02-barcode-engine](02-barcode-engine.md)

## Goal
An empty but correctly wired project: the app and the widget extension build, run in the simulator, and share an App Group and a Keychain group. Everything later stages need from project configuration is in place, so they only add Swift files.

## Why XcodeGen
An Xcode project file (`.pbxproj`) is a huge generated file that merges badly. XcodeGen generates it from a readable `project.yml`, much like a `package.json`. The `.xcodeproj` goes in `.gitignore`, and you run `xcodegen generate` after pulling or after adding files.

## `project.yml` outline
- `name: Cards`, `options.bundleIdPrefix: io.legiec`, `deploymentTarget.iOS: "26.0"`, `SWIFT_VERSION: 6.0`
- `settings.base.DEVELOPMENT_TEAM: ${DEVELOPMENT_TEAM}`. Read it from the environment or a git-ignored `local.yml` included via `include:`, so the Team ID is never committed. For simulator-only work it can stay empty (`CODE_SIGN_STYLE: Automatic`, sign to run locally).
- **targets:**
  - `Cards` (`application`):
    - sources `Cards`, `Shared`
    - dependency on `CardsWidget` (embed)
    - entitlements file with `com.apple.security.application-groups: [group.io.legiec.cards]` and `keychain-access-groups: [$(AppIdentifierPrefix)io.legiec.cards.shared]`
    - Info.plist: `CFBundleURLTypes` with scheme `cards`, `CFBundleDisplayName: Cards`, `UILaunchScreen: {}`
  - `CardsWidget` (`app-extension`):
    - sources `CardsWidget`, `Shared`
    - Info.plist `NSExtension.NSExtensionPointIdentifier: com.apple.widgetkit-extension`
    - same entitlements as the app
    - bundle id `io.legiec.cards.widget`
  - `CardsTests` (`bundle.unit-test`): sources `CardsTests`, depends on `Cards`, host application `Cards`
- `schemes.Cards`: build `Cards`, test `CardsTests`
- `packages:` stays empty for now. Stage 2 adds the barcode library.

## Steps
1. `git init` in `~/Projects/widgets-ios`, and set the author to "Bartosz Legięć".
2. Write `.gitignore` and `project.yml`, plus the placeholder Swift files:
   - The app shows `Text("Cards")`.
   - The widget is a `StaticConfiguration` that shows `Text("Hello")` so the extension is valid.
3. `xcodegen generate`, then build for the simulator.
4. Run in the simulator (`xcrun simctl boot`, `xcodebuild … -derivedDataPath build`, then `xcrun simctl install` + `launch`) and take a screenshot.
5. Check that the widget appears in the simulator's widget gallery. This is a manual step: long-press the home screen → + → search "Cards".
6. Smoke test: `#expect(true)`, just to prove the test target runs.
7. Commit: "Scaffold XcodeGen project with app and widget targets".

## Gotchas
- Widget extensions need the host app's bundle ID as a prefix (`io.legiec.cards.widget`). XcodeGen won't enforce this.
- App Groups and Keychain groups need a signing team on a real device. The simulator doesn't enforce them strictly, so real-device verification waits until stage 8. Ask the user for their Team ID then, not now.
- Keep `Shared/` free of `@main`, and of any API that's unavailable in extensions (e.g. `UIApplication.shared`).
