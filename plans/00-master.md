# Master plan: native loyalty-card widgets for iOS

This is the entry point. Each stage has its own detailed plan in this folder. Work through them in order: a stage starts only after the previous stage's acceptance criteria pass.

## Why

Put loyalty-card barcodes, including Żappka's rotating TOTP code, on the iPhone Home Screen as **native WidgetKit widgets**, with a native editor to create them.

This is **its own product**. It doesn't import, read, generate or stay compatible with anything from the earlier attempts (`~/Projects/widgy`, `~/Projects/widgets`). Cards are created fresh in the app. What was learned back then (the Żappka payload format, the brand colours) is written into these plans as plain facts. The one exception: the brand logo PNGs were copied once from `~/Projects/widgets/public/logo/` into the asset catalog.

**Goal:** a native SwiftUI app with real WidgetKit widgets. No server, no JS engine, no third-party widget host. It has an editor with a **live preview of every option while editing**, presets for the common cards, and Żappka.

## Decisions (already made with the user)
| Topic | Decision |
|---|---|
| Location | New repo `~/Projects/widgets-ios`, with the project generated by **XcodeGen**. `project.yml` is the source of truth; the `.xcodeproj` is not committed. |
| iOS target | **iOS 26.** The user is fine with iOS 27, but the installed toolchain is Xcode 26.6 (iOS 26 SDK). The target can go up once Xcode 27 is installed. |
| Card model | A library of cards in the app. Each widget is configured (long-press → Edit widget) to show one card, at any size. |
| Barcodes | **zxing-cpp** via SPM (`ZXingCpp`), with **ZXingObjC** as the fallback. Must support PDF417 and QR plus the common 1D codes. |
| Żappka payload | `https://srln.pl/view/dashboard?ploy=<userId>&loyal=<totp>`, encoded as **PDF417**. TOTP: SHA1 / 6 digits / 30 s, hex secret. |
| Żappka credentials | **Typed or pasted** into the editor (User ID + secret). No network calls to Żabka. An in-app login (the user has a separate reverse-engineering repo) comes later and plugs into the same seam. |
| Storage | SwiftData in the App Group container. The secret goes in the shared Keychain. |
| Migration | **None.** No `.widgy` import, no legacy URL/string formats. Cards are set up fresh in the app. |
| Design | **Widgets look exactly like the user's widgy cards** (white card, vertical-gradient header with a white logo, big code with a caption notch); spec measured from [`reference/`](reference/) in stage 5. The **app UI** is plain native iOS, not widgy's web UI. |

## Mental model (for a web developer)
| Web concept | iOS equivalent here |
|---|---|
| React component | SwiftUI `View` (a struct with a `body`) |
| react-hook-form bound to a model | `Form` with `@Bindable var card` (two-way bindings with `$card.name`) |
| DB table + ORM | SwiftData `@Model class Card` + `@Query` |
| `.env` secrets / secure cookie | Keychain |
| Two services sharing a DB | App target + widget extension target sharing an **App Group** container |
| A component's props schema | `WidgetConfigurationIntent` (what "Edit widget" shows) |
| SSR snapshots on a schedule | WidgetKit **timeline**: you hand iOS a list of `(date, view state)` entries, and iOS renders them. You don't render on demand. |
| Deep link / route | `widgetURL(URL("cards://card/<id>"))` → `onOpenURL` in the app |
| `package.json` | `project.yml` (XcodeGen) + SPM packages |

```

│ CardListView → CardEditorView        │        │ SelectCardIntent (pick a card)   │
│   └─ LivePreviewPanel (all options)  │        │ Provider → timeline entries      │
│ CardFullscreenView (checkout mode)   │        │ CardWidgetView → CardView        │
│                                      │        │ RefreshIntent (button)           │
└──────────────┬───────────────────────┘        └───────────────┬──────────────────┘
               │            Shared/ (compiled into both)         │

```

## Conventions (all stages)
- **Identifiers:**
  - bundle `io.legiec.cards` (widget: `io.legiec.cards.widget`)
  - App Group `group.io.legiec.cards`
  - keychain group `$(AppIdentifierPrefix)io.legiec.cards.shared`
  - URL scheme `cards`
  - The app's display name is still open (placeholder "Cards").
- **Code:** Swift 6 language mode with strict concurrency. SwiftUI only (no UIKit unless unavoidable). No third-party dependencies apart from the barcode library.
- **Files:** `Shared/` is pure logic and views, with no app-only APIs, because the widget compiles it too.
- **Tests:** Swift Testing (`import Testing`, `@Test`, `#expect`) in `CardsTests/`.
- **Secrets:** Never print or log the Żappka secret, in code or in test output. Tests use made-up secrets only; real credentials never enter the repo.
- **Build/test command** (used by every stage):
  `xcodegen generate && xcodebuild -scheme Cards -destination 'platform=iOS Simulator,name=iPhone 17 Pro' build test`
  If the simulator name differs, find it with `xcrun simctl list devices available`.
- **Commits:** one commit per stage (or per sub-step if a stage is big). Multi-line messages use multiple `-m` flags.

## Known facts (carried over as knowledge, not as dependencies)
- **Żappka payload:** `https://srln.pl/view/dashboard?ploy=<userId>&loyal=<totp>`, as PDF417. TOTP is RFC 6238, HMAC-SHA1, 6 digits, 30 s. The secret is hex; strip whitespace and lowercase it before use.
- **Brand colours** (gradient start → end): Żappka `#01B15B`→`#00A335`, Biedronka `#9a0100`→`#ff0011`, Rossmann `#C20225`→`#A2021F`, parkrun `#fea301`→`#fe7e01`, Empik `#2A2A2A`→`#000000`, Custom `#ff00ff`→`#ff0000`.
- **Widget look:** see the `reference/` images and the stage 5 spec.
- **Rotating codes need a freshness cue:** a clock or countdown on the card showed at a glance whether the code was current.

## Out of scope (for now)
- Importing from widgy or widgets (`.widgy` files, old URLs): deliberately dropped
- Żabka login / automatic credential fetching (a later stage, using the user's reverse-engineering repo)
- Lock Screen / StandBy / Control Center widgets, Apple Watch, iCloud sync
- Apple Wallet passes: they need a Pass Type ID certificate, and dynamic TOTP doesn't fit Wallet well
